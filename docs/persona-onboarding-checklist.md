# Persona Onboarding Checklist

## Purpose
This checklist helps teams onboard new team members or update role-specific responsibilities when roles evolve. Use this as a template to ensure consistent onboarding and clear role definition.

---

## For New Team Members

### Pre-Onboarding (Before Day 1)
- [ ] Identify the persona/role for the new team member
- [ ] Assign an onboarding buddy or mentor
- [ ] Prepare access credentials and tool accounts
- [ ] Add to relevant communication channels (Slack, Teams, etc.)
- [ ] Schedule initial 1:1 with manager and key stakeholders

### Week 1: Orientation
- [ ] Review the relevant persona document in [octoacme-roles-and-personas.md](octoacme-roles-and-personas.md)
- [ ] Review project overview and current roadmap
- [ ] Review all relevant process documentation:
  - [ ] [Project Initiation Guide](octoacme-project-initiation.md)
  - [ ] [Project Planning](octoacme-project-planning.md)
  - [ ] [Execution & Tracking](octoacme-execution-and-tracking.md)
  - [ ] [Release & Deployment](octoacme-release-and-deployment.md)
  - [ ] [Risk Management & Communication](octoacme-risks-and-communication.md)
  - [ ] [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)
- [ ] Set up development environment (if applicable)
- [ ] Review team norms and communication practices
- [ ] Introduce to cross-functional team members
- [ ] Review current sprint/iteration goals

### Week 2-4: Integration
- [ ] Shadow role-relevant meetings and activities
- [ ] Start contributing to assigned tasks with buddy support
- [ ] Review role-specific tools and workflows
- [ ] Understand escalation paths and communication channels
- [ ] Participate in sprint ceremonies (standup, planning, retrospectives)
- [ ] Complete any required training or certifications

### 30-Day Check-in
- [ ] Review progress with manager
- [ ] Clarify role expectations and success metrics
- [ ] Identify any gaps in knowledge or resources
- [ ] Adjust onboarding plan as needed
- [ ] Gather feedback on onboarding experience

### 60-Day Check-in
- [ ] Assess role integration and contribution level
- [ ] Identify opportunities for growth and skill development
- [ ] Refine goals and priorities
- [ ] Update team on onboarding completion

### 90-Day Review
- [ ] Conduct formal performance review or check-in
- [ ] Confirm full role transition and independence
- [ ] Set long-term goals and development plans
- [ ] Document lessons learned for future onboarding improvements

---

## For Role Updates or Persona Changes

When existing team members change roles or when role responsibilities evolve:

### Planning Phase
- [ ] Document the reason for role change or update
- [ ] Review updated persona documentation
- [ ] Identify knowledge gaps between old and new role
- [ ] Determine if additional training is needed
- [ ] Create transition timeline with milestones

### Transition Activities
- [ ] Update team communication (announce role change)
- [ ] Transfer responsibilities from previous role
- [ ] Shadow new role activities if transitioning roles
- [ ] Update project documentation with new role assignments
- [ ] Adjust meeting attendance and responsibilities
- [ ] Update access permissions and tool configurations

### Integration
- [ ] Regular check-ins with manager (weekly for first month)
- [ ] Identify a mentor in the new role (if available)
- [ ] Participate in role-specific activities and ceremonies
- [ ] Build relationships with new stakeholders
- [ ] Review and update personal goals to align with new role

### 30-Day Transition Review
- [ ] Assess transition progress
- [ ] Address any challenges or blockers
- [ ] Gather feedback from key stakeholders
- [ ] Adjust support and resources as needed

## Role-Specific Onboarding Supplements

### For Developers
- [ ] Set up Git repository access and branching strategy
- [ ] Review code style guides and contribution guidelines
- [ ] Complete first code review (as reviewer and reviewee)
- [ ] Deploy first feature or bug fix
- [ ] Review CI/CD pipelines and deployment processes

### For QA/Test Engineers
- [ ] Review test strategy and test plans
- [ ] Set up test environments and tools
- [ ] Review bug tracking and reporting process
- [ ] Execute first test case and report findings
- [ ] Understand automation framework and capabilities

### For UX/UI Designers
- [ ] Review design system and component libraries
- [ ] Set up design tools (Figma, Sketch, etc.)
- [ ] Review user research findings and personas
- [ ] Participate in design critique session
- [ ] Deliver first design deliverable

### For Technical Writers
- [ ] Review documentation style guide
- [ ] Set up documentation tools and repositories
- [ ] Review existing documentation structure
- [ ] Complete first documentation update or new content
- [ ] Understand release notes process

### For Business Analysts
- [ ] Review business requirements templates
- [ ] Understand business stakeholders and their needs
- [ ] Review existing process documentation
- [ ] Participate in requirements gathering session
- [ ] Create first user story or requirement document

### For Support Engineers/Customer Success
- [ ] Set up support ticketing system access
- [ ] Review knowledge base and support documentation
- [ ] Shadow experienced support sessions
- [ ] Handle first customer interaction with supervision
- [ ] Learn escalation procedures and SLAs

### For Security/Compliance Leads
- [ ] Review security policies and compliance requirements
- [ ] Set up security scanning tools and access
- [ ] Review threat model and security architecture
- [ ] Conduct first security review
- [ ] Understand incident response procedures

### For Product Managers
- [ ] Review product vision and strategy
- [ ] Understand customer segments and user personas
- [ ] Review product roadmap and backlog
- [ ] Participate in customer interviews or research
- [ ] Lead first backlog refinement session

### For Project Managers
- [ ] Review project management methodology (Agile, Waterfall, etc.)
- [ ] Set up project tracking tools (Jira, Azure DevOps, GitHub Projects)
- [ ] Review risk register and mitigation strategies
- [ ] Facilitate first project meeting
- [ ] Create first status report

---

## Documentation Update Process

When role definitions or responsibilities change:

- [ ] Update the relevant persona section in [octoacme-roles-and-personas.md](octoacme-roles-and-personas.md)
- [ ] Review and update cross-references in other process documents
- [ ] Notify team of documentation changes
- [ ] Update this checklist if new onboarding steps are identified
- [ ] Request review from affected team members
- [ ] Archive old version if significant changes were made

---

## Feedback and Continuous Improvement

- [ ] Collect onboarding feedback at 30, 60, and 90 days
- [ ] Review onboarding metrics (time to productivity, satisfaction scores)
- [ ] Update checklist based on lessons learned
- [ ] Share successful onboarding practices with other teams
- [ ] Iterate on role definitions based on real-world experience
